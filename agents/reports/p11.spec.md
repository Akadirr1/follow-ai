## Measured by the coordinator (2026-08-21)
- **Gemini REST** `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`,
  header `x-goog-api-key`, body `{contents:[{parts:[{text}]}],
  systemInstruction:{parts:[{text}]}, generationConfig:{responseMimeType:
  "application/json", responseSchema:{...}, maxOutputTokens, temperature,
  thinkingConfig:{thinkingBudget}}}` → 200; `candidates[0].content.parts[0].text`
  is the JSON string; `usageMetadata.{promptTokenCount,candidatesTokenCount,
  thoughtsTokenCount}`. `gemini-2.5-flash` answered a schema'd call correctly and
  spent 42 thinking tokens by default → set `thinkingBudget: 0` for flash unless
  env overrides. Gemini `responseSchema` is an OpenAPI subset: uppercase types
  (`OBJECT`, `ARRAY`, `STRING`), `nullable: true` instead of `type:["string",
  "null"]`, no `additionalProperties`, no guaranteed `minItems/maxItems` → our
  runtime validator stays authoritative. Available: `gemini-2.5-flash`,
  `gemini-2.5-pro`, `gemini-2.5-flash-lite`, `gemini-3.*` previews.
- **NVIDIA NIM** is OpenAI-compatible: `POST https://integrate.api.nvidia.com/v1/chat/completions`,
  `Authorization: Bearer`, `{model, messages:[{role:"system"},{role:"user"}],
  response_format:{type:"json_object"}, max_tokens, temperature:0}` →
  `choices[0].message.content` JSON string; `usage.{prompt_tokens,
  completion_tokens}`; `choices[0].finish_reason` (`stop`/`length`).
  `meta/llama-3.3-70b-instruct` answered correctly. Also available:
  `nvidia/llama-3.3-nemotron-super-49b-v1.5`, `nvidia/llama-3.1-nemotron-ultra-253b-v1`,
  `mistralai/mistral-large-2-instruct`, `deepseek-ai/deepseek-v4-flash-0731`.
  `json_object` mode requires the word "JSON" in the prompt (our system prompt
  already says it in "ÇIKTI").

## Design (arch addendum §H — write it at the top of your report)
1. **Provider interface** = the existing `ClaudeClient { summarise(input):
   Promise<ClaudeOutcome> }` in `_shared/anthropic.ts`. Do not rename what tests
   import; add neutral aliases (`SummariseClient`, `SummariseOutcome`). Reuse the
   prompt block (`prompt.ts`), the runtime validator, `TokenUsage` and the
   failure codes unchanged, so every provider is judged by the same rules.
2. **`_shared/providers/gemini.ts`** and **`_shared/providers/nvidia.ts`**:
   portable TS, `fetchImpl` injected, no SDKs. HTTP → failure codes: 429
   `rate_limited` (retryable; honour `Retry-After`), 5xx/529 `server_error`/
   `overloaded` (retryable), 400/404 `bad_request`, 401/403 `auth`/`permission`
   (non-retryable), abort → `timeout` (retryable), no candidates or
   `finishReason` `SAFETY`/`RECITATION` → `refusal` (non-retryable),
   `MAX_TOKENS`/`length` → `output_truncated` (retry once with the escalated
   budget, as Claude does). 60 s request timeout via AbortController. Never log
   article text or keys; Gemini key only in the header, never in the URL.
3. **`_shared/ai-provider.ts`** — `resolveAiProvider(env, getSetting)`:
   `AI_PROVIDER` ∈ `gemini | nvidia | anthropic | auto` (default `auto` = first
   of gemini → nvidia → anthropic whose key resolves). Keys: env
   `GEMINI_API_KEY` / `NVIDIA_API_KEY` / `ANTHROPIC_API_KEY` first, else Vault via
   `getSetting('aigundem_gemini_api_key' | 'aigundem_nvidia_api_key')`
   (Anthropic stays env-only). Models: `GEMINI_MODEL` default `gemini-2.5-flash`,
   `NVIDIA_MODEL` default `meta/llama-3.3-70b-instruct`, `ANTHROPIC_MODEL` as
   today. Returns `{provider, model, client, fallback?}` or `{provider: null}`.
   **Fallback:** when the primary returns a *retryable* failure and a second
   provider has a key, try it once inside the same job before retry/backoff.
   The `model` column carries the provider's model string
   (`gemini-2.5-flash`, `meta/llama-3.3-70b-instruct`), which keeps the cache
   key honest.
4. **Wire both functions through the resolver.** `process-enrichments`:
   `hasApiKey` := a provider resolved; `skipped:'no_api_key'` only when none.
   `request-enrichment`: `hasApiKey` **and the `model` passed to `findSummary` /
   `enqueueJobCharged` must come from the same resolver** — otherwise the cache
   key diverges and every request is a permanent miss. Memoise Vault lookups
   per invocation like `secret.ts` does.
5. **Migration `202608210011_ai_provider_keys.sql`:** re-create
   `aigundem.internal_get_setting` with the allow-list
   `('aigundem_automations_secret', 'aigundem_gemini_api_key', 'aigundem_nvidia_api_key')`,
   same security shape (definer, `search_path=''`, service_role only),
   re-assert revoke/grant, `notify pgrst, 'reload schema'`. Extend sql-lint to
   pin the allow-list.
6. **Daily cap stays** (`AI_DAILY_CAP`, default 200): Google AI Studio's free
   tier is RPM/RPD-limited; 429 → existing backoff. Keep `max_jobs` as the cron
   body sends it.

## Tests (Jest, fake fetch)
Per provider: request shape (headers, schema / JSON mode, system prompt first),
happy path → validated payload + usage, Turkish `translation=null` rule, 429
with `Retry-After`, 5xx, 401, timeout/abort, truncated (`MAX_TOKENS`/`length`),
safety stop, malformed JSON → `schema_not_json`. Resolver: env beats Vault;
`auto` order; no key anywhere → null; request-enrichment and the worker resolve
the **same** model string. Fallback: primary 429 → secondary success → `ready`
with the secondary's model; primary non-retryable → no fallback. Existing
Claude tests unchanged.
