## 4. Client `unavailable` and render-test judgment

**Verified by inspection:** the Supabase repository maps wire `status: 'unavailable'` before its queued/unknown fallbacks; the domain has a distinct terminal variant. `useEnrichment` returns `false` from `refetchInterval` for every non-queued result and gives terminal answers infinite stale time. The article screen computes `unavailable` before `pending`, renders exactly `Bu haber için özet üretilemiyor; kaynağa git.`, and suppresses the spinner, “Özet hazırlanıyor”, bullet count, and Claude credit.

**Verified by execution:** the focused three-suite run reported `62/62` assertions passing. The dedicated repository tests decode `unavailable/no_content`, preserve an unfamiliar reason, and default a missing reason. The hook tests use fake timers and count calls: queued stops exactly at `ENRICHMENT_MAX_POLLS`, `{ maxPolls: 2 }` makes exactly 2 calls, unavailable remains at exactly 1 initial call after advancing beyond the cap, and no warning fires. The screen render test uses the real `ArticleScreen` with a repository seam, asserts the exact unavailable copy and absence of pending/credit/count, and presses the real “Kaynağa git” action; a separate test proves an existing summary wins over a later unavailable response.

**Judgment:** these are meaningful behavioral tests rather than snapshots or text lints, and their layering (wire decoder, hook scheduler, real screen render) is appropriate. They are not native-device tests. The focused run also emits several unrelated React `act(...)` warnings and the open-handle hang described in item 1, so the test signal is functionally strong but operationally noisy.

- Digest reaching five enriched items and becoming `ready`; the current no-key live smoke can only show `preparing`/missing enrichments.
- The complete local-notification payload based on a live ready digest.

### Other server/runtime gaps not requiring those credentials

- B2 against a genuinely stalled remote server (only deterministic stream behavior executed).
- B4 with two concurrent live finalizers and a live ready/fewer-than-five boundary.
- N5's NULL guard through the live service-role RPC.
- Reproducible fresh Supabase project creation/deployment (N6).
- Exact UTF-8 streaming enforcement for request bodies (N2, still absent).

## Remaining gaps and release verdict

The **single most important remaining gap** is the live Claude-success loop: enqueue → worker/model → validated cached summary/translation → article ready state → five-item digest. It is the product's central promise and today has no execution evidence because no Anthropic key exists; passing the no-key queued behavior is necessary but cannot substitute for it.

Other non-blocking but concrete follow-ups are: clean the Jest open handles/`act` warnings; implement a streaming UTF-8 request-body cap (N2); make migrations/deploy config reproducible (N6); remove the now-false B1 comment; and carry Supabase add-source's `created:false` to the UI, which currently reports silent success and leaves the list unchanged instead of saying “Bu kaynak zaten ekli.” Client retry de-duplication was applied to feed/search, while article/sources/digest still have layered retry budgets.

**Release verdict:** the candidate is suitable to advance to controlled native-device QA and a controlled live-Claude validation: the release gate is green, both web bundles are clean, the no-key/live read-and-request path works, and rev-003's four blockers are closed in code with the limitations above. It is **not a defensible public production launch yet**. The human should first provide the server-side Anthropic secret for one bounded end-to-end smoke, run the native matrix on iOS and Android (especially notifications/persistence), and either close or explicitly accept N2, N6, and the Jest teardown debt.
