(Gemini 2.5-flash via P11, ~3 s) → `200 ready` with 3 Turkish bullets +
translation. **But only `request-enrichment` ever enqueues a job** (grep over

Istanbul window holds **122 enrichable articles** and **0** summaries that a
user did not ask for, so `build-digest finalize` stays `preparing / missing 5`

sources before 06:50. The digest must not depend on that.

2 min (`max_jobs` as sent by the 0008 job body — read it); finalize 03:30/40/50
UTC. So ~22 worker ticks sit between prepare and the first finalize.

## Change
1. **Migration `202608210012_digest_candidates.sql`:**
   `aigundem.internal_enqueue_digest_candidates(p_date date, p_model text,
   p_prompt_version text, p_per_source integer default 2, p_limit integer
   default 15)` returning `(enqueued integer, already integer, candidates
   integer)`. Window = the same derivation 0010's digest functions use
   (`v_end = (p_date + 05:00) Europe/Istanbul`, 24 h back). Candidates: articles
   from `active` sources, `content_text` not null/empty, in the window, **no
   row in `article_summaries` for (article_id, content_hash, p_prompt_version,
   p_model)**; rank newest-first per source, take `p_per_source` per source,
   then the newest `p_limit` overall (deterministic order: published_at desc,
   id desc). Insert into `private.ai_jobs` with `on conflict … do nothing`
   (same unique key 0010 relies on) — **no rate-limit charge** (this is the
   system's own spend; the worker's global `AI_DAILY_CAP` still bounds it).
   Validate arguments (date range like 0010; `p_per_source` 1..5; `p_limit`
   1..50; model/prompt_version lengths like 0010). SECURITY DEFINER,
   `search_path=''`, schema-qualified, no dynamic SQL, service_role only, plus
   the `public.aigundem_internal_enqueue_digest_candidates` shim (addendum
   §C.1). `#variable_conflict use_column` if any OUT name collides.
2. **`build-digest` `prepare` phase:** after `internal_digest_prepare`, resolve
   the provider with P11's `resolveAiProvider` (same env/Vault path as the
   worker — the model string MUST be the worker's, or the summaries land under
   a key finalize never matches) and call the new wrapper with that model and
   `PROMPT_VERSION`. Env knobs: `DIGEST_PER_SOURCE` (default 2),
   `DIGEST_CANDIDATES` (default 15). Return `enqueued/already/candidates` in
   the prepare response and log them. `finalize` unchanged. When no provider
   resolves, skip enqueueing and say so (`enqueued: 0, reason: 'no_provider'`).
3. **Tests:** sql-lint-0012 (pins the no-summary anti-join, per-source rank,
   `on conflict`, grants, `search_path`); build-digest unit tests for the
   prepare path (provider resolved → wrapper called with the resolver's model;
   no provider → not called; response shape); existing tests unchanged.
