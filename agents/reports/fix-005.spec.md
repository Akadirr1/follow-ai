## Measured on the live project (coordinator, 2026-08-21 11:05)
`request-enrichment` v2 now answers **`200 {"status":"unavailable","reason":
"no_content","client_request_id":"…"}`** for articles with no body (Hugging
Face: 100 live rows, `content_quality='excerpt'`, `content_text`/`excerpt`
NULL). The client has never seen this variant:
`src/data-access/supabase/repositories.ts` (the "unrecognised body" branch)
maps it to `queued`, and `src/data-access/hooks.ts useEnrichment` then polls it
`ENRICHMENT_MAX_POLLS` times showing "Özet hazırlanıyor". Terminal state, must
not poll. Independent verification `agents/reports/ver-003.md` §4 lists the
automated gaps below.

## Changes
1. **Domain** `src/domain/types.ts`: `EnrichmentResult` gains
   `| { status: 'unavailable'; reason: 'no_content' | string }`.
2. **Supabase repository**: map `data.status === 'unavailable'` (any HTTP 2xx)
   to that variant; keep the unknown-body → `queued` fallback last.
   **Mock repository** `src/data-access/mock/repositories.ts`: return
   `unavailable/no_content` for fixture articles whose body and excerpt are
   empty (add one such fixture if none exists) so mock mode exercises the path.
3. **Hook** `useEnrichment`: `unavailable` never refetches (`refetchInterval`
   false) and is cached like `ready` (`staleTime: Infinity` for that status if
   the hook sets per-status staleness; otherwise document why not needed).
4. **Article screen** `app/article/[id].tsx`: when `enrichment.data.status ===
   'unavailable'`, render the existing summary block in its empty/terminal
   form with the string **"Bu haber için özet üretilemiyor; kaynağa git."**
   and the existing "Kaynağa git" action; no spinner, no "hazırlanıyor".
   Theme tokens only; no new hex.
5. **Tests (close ver-003 gaps):**
   a. repository: `200 unavailable` → variant; mock parity test.
   b. **`useEnrichment` poll cap**: render the hook with a fake repository that
      returns `queued` forever using fake timers; assert exactly
      `ENRICHMENT_MAX_POLLS` refetches, the warning once, then no further
      fetch; and that `unavailable` triggers **zero** refetches.
   c. `QueryProvider` restore-before-fetch: mount a query with a fetch spy and
      assert the persisted value renders before the spy is called.
   d. screen: article with `unavailable` shows the new string and the source
      link; never shows "Özet hazırlanıyor".
   e. feed: after `openArticle`, the card's read styling/“N yeni” count
      updates (one render test).
