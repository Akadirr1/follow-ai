## B1 — native KV called the module namespace, not the exported store

**Reproduced before fixing.** `node_modules/expo-sqlite/build/Storage.js:396-401`
reads `export const AsyncStorage = new SQLiteStorage(...)`, `export default
AsyncStorage`, `export const Storage = AsyncStorage`. The namespace has no
`getItem` of its own, so P8's `Store.getItem(key)` was `undefined(...)` on every
call — a `TypeError` the per-call `catch` turned into "read failed", i.e. an app
that looked like it persisted and did not.

```ts
-    const Store = require('expo-sqlite/kv-store') as { getItem…; setItem…; removeItem… };
-    return { async getItem(key) { try { return await Store.getItem(key); } … } };
+export function resolveNativeStore(module: unknown): KvStore | null {
+  if (isKvLike(module)) return module;              // a namespace that IS the store
+  if (typeof module === 'object' && module !== null) {
+    const namespace = module as { default?: unknown; Storage?: unknown };
+    const exported = namespace.default ?? namespace.Storage;
+    if (isKvLike(exported)) return exported;
+  }
+  return null;
+}
+
+export function createNativeStore(loadModule: () => unknown, onFallback = warnMemoryFallback) {
+  …
+  const store = resolveNativeStore(module);
+  if (!store) { onFallback('expo-sqlite/kv-store exported no getItem/setItem/removeItem'); return memoryStore; }
+  return guarded(store, 'kv-store');
+}
```

`isKvLike` validates all three methods, so a future export change fails over
loudly instead of silently.

**Test** — `src/storage/__tests__/kv.test.ts`, using the *real* export shape
(`{__esModule, SQLiteStorage, AsyncStorage, Storage, default}`) rather than a
hand-shaped fake:
`unwraps the instance from the real {default, Storage} export shape`,
`reads and writes reach the exported instance, not the namespace` (asserts the
value lands in the instance's own Map **and** that no fallback fired),
`returns null when nothing on the module is store-shaped` — which is the exact
defect: a namespace with no `getItem`. Plus `prefers default, and falls back to
Storage`, the require-throws path, and a throwing-method path.

### A regression this fix caused, and how it was found

Making `createNativeStore` exported (for the test) put its `require` in the
**web** module graph, and `expo-sqlite`'s web worker imports a `.wasm` Metro
cannot resolve. `expo export --platform web` failed outright:

```
Error: Unable to resolve module ./wa-sqlite/wa-sqlite.wasm from
  node_modules\expo-sqlite\web\worker.ts
Import stack: … expo-sqlite\kv-store.js | import "./build/Storage"
```

A3 caught it. Fixed by keeping the real `require` in a **private**
`loadNativeModule()` referenced only from the pruned native branch, and passing it
in at the call site — the exported function now contains no `require`:

```ts
function loadNativeModule(): unknown { return require('expo-sqlite/kv-store'); }
export const kv: KvStore =
  Platform.OS === 'web' ? createWebStore() : createNativeStore(loadNativeModule);
```

## N2 — the cursor brand is now required

```diff
-  readonly [cursorBrand]?: true;
+  readonly [cursorBrand]: true;
```

`{publishedAt, id}` no longer satisfies `Cursor`. `src/data-access/cursor.ts` is
the single owner: `cursorOf` (the one cast in the codebase), `encodeCursor`,
`decodeCursor` (validates type **and** non-emptiness, warns and returns null
otherwise), `isAfterCursor`, `keysetFilter`. The mock mapper's duplicate
`cursorOf`/`isAfterCursor` are gone; it re-exports the shared ones and exposes
`cursorOfArticle` built on them, so both adapters mint cursors the same way.

The change proved itself immediately: `npm run typecheck` failed on my own P6
test, which had been fabricating a cursor literal —

```
src/data-access/__tests__/supabase-repositories.test.ts(122,40): error TS2345:
  Property '[cursorBrand]' is missing … but required in type 'Cursor'.
```

— fixed by routing it through `cursorOf`.

**Test** — `contracts.test.ts` "cursor opacity (N2)": encode/decode round-trip;
`rejects a decoded payload that is not a cursor` (wrong types and empty strings);
the strict `(publishedAt, id)` DESC ordering including the *cursor row itself is
not after itself*, which is what stops a page repeating its last item; and an
end-to-end paging check where the cursor survives the serialisation a persisted
query cache would apply and the second page shares no ids with the first.

  `hideAsync` effect itself is not exercised by any test (no render test mounts
  `ThemedApp`).
