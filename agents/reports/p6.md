## 2. Query-key scheme

Every key begins with the version segment, and `shouldDehydrateQuery` persists
**only** keys that do:

| Hook | Key |
|---|---|
| `useFeed(filter)` | `['v1','feed', '{"category":…,"sourceIds":[…sorted]}']` |
| `useArticle(id)` | `['v1','article', id]` |
| `useSearch(q)` | `['v1','search', q.trim().toLowerCase()]` |
| `useSources()` | `['v1','sources']` |
| `useDigest()` | `['v1','digest']` |
| `useEnrichment(id)` | `['v1','enrichment', id]` |

The feed filter is normalised (sorted source ids, `null` category) so two
equivalent filters share one cache entry rather than fetching twice. Cache buster
is `aigundem-v1-repo1` — it embeds `REPOSITORY_CONTRACT_VERSION`, so a DTO shape
change invalidates the persisted blob automatically instead of hydrating the wrong
type.

## 4. DTO mapping

`public.aigundem_feed_articles_v1` → `Article`:

| Column | DTO field | Note |
|---|---|---|
| `article_id` / `source_id` / `source_name` | `id` / `sourceId` / `sourceName` | |
| `source_slug` | `tile` | first two alphanumerics, upper-cased — the DB has no badge column |
| `title`, `canonical_url`, `published_at`, `category`, `language` | same names | `publishedAt` is already ISO |
| `content_text` ?? `excerpt` ?? `''` | `bodyOriginal` | fullest text available; the source-language text |
| `summary_tr` (text[3]) | `summary.bullets` | padded + warned if not 3 |
| `translation_tr` | `summary.translationTr` | forced `null` when `not_required` |
| `translation_state` + `language` | `summary.translationState` | `tr` ⇒ `not_required` regardless of the column |
| `summary_ready = false` | `summary.translationState = 'pending'` | **the no-Anthropic-key state** (addendum §E) — bullets `['','','']`, translation `null` |

`aigundem_sources_v1` → `Source` (`status='active'` ⇒ `isActive`, `is_default` ⇒
`isDefault`). `aigundem_digests_v1` + `aigundem_digest_items_v1` → `Digest`:
`generated_at` ⇒ `preparedAt`, `blurb_tr` ⇒ `blurb`. The item view carries **only**
`article_id` and `blurb_tr`, so `title`/`sourceName`/`category` come from a third
query against the feed view keyed by article id; an item whose article is no longer
readable keeps its position with empty labels and warns.

## 6. Decisions

1. **Asked before building on a contradiction.** The brief wants
   `SourceRepository` to read `is_default` rows and `DigestRepository` the latest
   digest, *and* forbids `.schema()`. Measured, neither had a public shim
   (`PGRST205`), and `aigundem` is not exposed (`PGRST106`) — so both could not
   hold. I built against named public shims with a typed-error fallback and asked;
   the coordinator applied migration 0007 creating exactly
   `aigundem_sources_v1` / `aigundem_digests_v1` / `aigundem_digest_items_v1`, which
   I then verified live (200 []) and pointed the constants at.
2. **`PGRST205`/`PGRST106` still map to `not_implemented`.** These shims are
   explicitly temporary. When they are dropped for `.schema('aigundem')`, the
   failure will name the missing surface instead of surfacing an unexplained error.
3. **Digest items need a third query.** The item view carries only `article_id` and
   `blurb_tr`, so titles come from the feed view. I merge client-side rather than
   ask the server lane for a wider view — it is one keyed lookup over at most five ids.
4. **`limit + 1` for keyset paging.** Fetching one extra row is how `hasMore` is
   known without a `count`, which on PostgREST costs a second scan.
5. **Edge config is injectable.** `env` is frozen (P1), which is right, but it made
   the Edge helper untestable without mocking the config module. `EdgeCallOptions`
   now carries an optional `config` beside `fetchImpl` — the same seam, one more
   field, no production behaviour change.
6. **Hook return types are inferred, not annotated.** TanStack's `Register`
   augmentation for `defaultError` does not reach the interface in this package's
   rolled-up `.d.ts`, so annotating `UseQueryResult<T, Error>` fails to compile. The
   hooks return the inferred type and `asDataError(query.error)` is the single
   sanctioned way to read a typed error — which is what P7 should use.
7. **Local user state is not a TanStack query.** There is no server, no staleness
   and nothing to revalidate; modelling it as server state would put a cache in
   front of the value that already *is* the truth.
8. **Idempotent setters, not toggles.** `setSaved(id, true)` / `setSourceEnabled(id,
   false)` state the desired value, so a retry cannot flip it back (arch-001 §4).
   Every Edge write carries a `client_request_id`.
9. **Query clients are cleared in tests.** `gcTime` is seven days, so a live
   `QueryClient` keeps GC timers pending and Jest will not exit — this actually hung
   a full `npm test` run until the tests started calling `client.clear()`.
10. **No new env var.** `src/config/env.ts` is unchanged; the three
    `EXPO_PUBLIC_*` vars P1 validates were sufficient.
