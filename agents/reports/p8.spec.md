## Goal
Replace the dark-only token file with a real theme system:
- `src/theme/palettes.ts`: semantic palette type + `dark` (existing values, same
  semantics) + `light` (exact board tokens: bg `#F4F6FB`, text `#0F1B33`, card
  `#FFFFFF`, border `#D8E0F0`, soft `#E7EEFB`, accent `#2563EB`; derive the
  remaining semantic slots — accentText, tile, inactive switch, input bg, danger,
  text alpha ramp — from the board's light section where present, otherwise by
  documented rule; list every derived value in the report).
- `src/theme/typography.ts` / spacing: theme-invariant values split out of tokens.
- `src/theme/ThemeProvider.tsx`: `ThemeProvider`, `useTheme()` (resolved palette +
  scheme), `useThemePreference()` (`'dark'|'light'|'system'`, setter). `system`
  resolves via `useColorScheme()` and re-resolves on OS change. Preference is
  persisted with `expo-sqlite/kv-store` (`npx expo install expo-sqlite`) behind a
  tiny `src/storage/kv.ts` adapter (get/set string; web fallback to
  `localStorage`/memory so `expo export --platform web` keeps working). Load the
  preference **before** the first painted frame (keep the splash up, same pattern
  as the font gate in `app/_layout.tsx`).
- Wire `app/_layout.tsx` (provider + `StatusBar` style from theme), the Settings
  theme segment (`Koyu / Açık / Sistem` becomes a real three-state control; the
  `TOASTS.theme` string and its toast are **deleted** from `src/store/types.ts` and
  the settings screen), and the shared components `Toast`, `Toggle`, `ArticleCard`,
  `EmptyState`, `DigestTimeSheet` to consume `useTheme()`. Screens other than
  Settings may keep importing tokens only if `src/theme/tokens.ts` becomes a
  thin re-export of the **dark** palette (so nothing breaks) — say so in the report;
  P7 finishes the screen-by-screen migration.
- `app.json`: `userInterfaceStyle: "automatic"`; splash/background stay dark.
