## 2. The new DTO variant

```ts
export type EnrichmentResult =
  | { status: 'ready'; summary: ArticleSummary }
  | { status: 'queued'; reason: string | null }
  | { status: 'unavailable'; reason: 'no_content' | string };
```

`unavailable` is **terminal**, and that is the whole point: `queued` means "come
back later", `unavailable` means "the server looked, there is no body, waiting
will not help". Keeping it as a flavour of `queued` — which is what the
unrecognised-body fallback did — is what produced the bug: 100 live Hugging Face
rows polled six times each behind "Özet hazırlanıyor" that could never resolve.

The literal union `'no_content' | string` keeps `no_content` documented and
autocompleting while still carrying a reason the client has not seen yet
(pinned by a test with `reason: 'paywalled'`). A reasonless `unavailable`
defaults to `no_content` rather than `null`, because the status already asserts
the reason exists.

**Order matters in the decoder.** `unavailable` is checked *before* both
`queued` branches and before the unknown-body fallback, so a future
`200 {status:'unavailable'}` with any other field shape still lands correctly.

## 3. One instruction carried out differently

§0b asked me to "remove the unreachable `duplicate_source` branch". **It is not
unreachable.** `src/data-access/mock/repositories.ts:141` raises
`duplicate_source` locally when the URL already matches a catalogue entry, so in
mock mode "Bu kaynak zaten ekli." is live, correct copy today. The premise holds
only for the *Supabase* path, where an existing feed is a 200 with
`created:false`.

So I removed the unreachable half and kept the reachable half:

- `CODE_MAP` no longer maps `duplicate_source`/`duplicate` — no deployed handler
  sends them (verified against `_shared/error.ts`'s `ErrorCode` union), and the
  existing test that asserted that mapping now asserts `parse_failed` instead.
- The `case 'duplicate_source':` copy in `AddSourceSheet` stays, with a comment
  saying it is mock-only.

**Still open, and outside these allowed paths:** showing "Bu kaynak zaten ekli."
after a *Supabase* 200 `created:false` needs the `created` flag carried through
`addSourceByUrl`'s `Result<Source>` and read where the success toast is raised —
`app/(tabs)/sources.tsx`, which fix-005 may not touch. Today that case silently
succeeds and the source list simply does not grow. Worth one follow-up hunk.

Two smaller notes on scope:

- **N2 was applied to feed and search only**, as written. `useArticle`,
  `useSources` and `useDigest` go through the same PostgREST path and still stack
  React Query's two retries on top of postgrest-js's own; the sources screen can
  therefore still spend ~24 s before showing an error. Same one-line change when
  you want it.
- **A4 holds structurally, not just by grep.** `pending` is now
  `!unavailable && (…)`, so the single remaining "Özet hazırlanıyor"
  (`app/article/[id].tsx:189`) cannot render while `unavailable` is true.

## 4. Tests: what each one fakes, and what that really proves

**21 new assertions** (store project 324 → 345). Two new files, five updated.

### `src/data-access/__tests__/enrichment-unavailable.test.tsx` (new, 12 tests)

The two halves fake at deliberately different depths.

- **Repository (5) — fakes the *network*.** A stub `fetch` answers exactly what
  the deployed v2 sends: `200 {"status":"unavailable","reason":"no_content"}`.
  Proves the **wire body** is decoded, not that a mock returned what it was told
  to. Also pins the ordering: an unknown body (`status:'something-new'`) still
  warns and falls back to `queued`, and `202` is still `queued`.
- **Mock parity (2) — no fake at all.** The real mock repository over the real
  fixtures. Proves mock mode reaches the same state, which is the only way a
  developer without credentials can see this screen.
- **Hook (5) — fakes the *repository*, counting calls, with fake timers.** The
  thing under test is *how many times React Query calls back*; a network stub
  would only add noise between the decision and the count. This is the ver-003
  §4 gap:
  - `queued` forever → exactly `ENRICHMENT_MAX_POLLS` (6) repository calls, the
    warning **once**, and — advancing four intervals past the cap and then three
    more — no further call. It proves the interval **stops scheduling itself**,
    not merely that it slows down.
  - `maxPolls: 2` → 2 calls, so the cap is the option, not a hard-coded constant.
  - `unavailable` → **1** call, ever, and no warning. This is the regression
    fix-005 exists for.
  - `ready` → 1 call.
  - A terminal answer reports `isStaleByTime(Infinity) === false`, which is the
    `staleTime` decision itself rather than a symptom of it.

### `src/providers/__tests__/restore-before-fetch.test.tsx` (new, 2 tests)

**Fakes the query function — a spy — and nothing else.** The real
`QueryProvider`, the real `createAsyncStoragePersister`, a Map-backed kv. Launch
once, let the persister write, unmount, launch again with a spy that would
resolve to different text: the persisted text renders and **the spy was never
called**. That is a statement about the provider's ordering, which the existing
`QueryProvider.test.ts` (round-trip only) could not make. The second test pins
the other direction: with nothing persisted the provider renders the empty state
rather than inventing one.

### `src/__tests__/screens.test.tsx` (+3)

- **Article, `unavailable`** — the new sentence renders, "Özet hazırlanıyor"
  does **not**, the count pill and the Claude credit are gone, and pressing

- **Feed, read state** — two articles, header reads "2 yeni"; pressing a card
  routes *and* the header becomes "1 yeni". The count is the visible proof that
  the read set was persisted through kv and read back, not just that a route

## 7. Rollback

Per change, smallest first:

- **The card copy only:** revert the `unavailable` branch in
  `app/article/[id].tsx`; the hook stops polling either way, so the fallback is a
  spinner that never resolves — worse, but not broken.
- **The whole terminal state:** revert `src/domain/types.ts`,
  `supabase/repositories.ts`, `mock/*` and the hook's `staleTime`. Behaviour
  returns to "poll six times, then give up".
- **N2 only:** set `retry: retryPolicy` back on `useFeed`/`useSearch`.
- **N1 only:** restore the old `CODE_MAP` body and drop the
  `NO_FEED_SERVER_CODES` block in `AddSourceSheet`.
- **B1 must not be rolled back** — every Edge write fails without it. If
  `randomUuidV4` ever needs to change, the only requirement is that it satisfies
  `/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`.

Removing `NO_CONTENT_ARTICLE` from `mockArticles()` reverts five test
expectations with it; it is the one change that touches what mock mode shows.
