Key shape decisions, all traceable to arch-001 §2:
`sources.feed_url_hash` and `articles.url_hash`/`content_hash` are 32-byte
sha256 (`octet_length = 32` checks); `articles` carries a denormalised
`category` so feed queries never join `sources`; `article_summaries.summary_tr`
is checked element-by-element for exactly three non-empty bullets (a CHECK
constraint may not contain a subquery, so `unnest`/`bool_and` was unavailable);
keyset pagination is served by `(published_at DESC, id DESC)` and
`(source_id, published_at DESC, id DESC)`; search is served by a stored
generated `search_tsv` column with a GIN index using the `simple` config.

There is **no INSERT, UPDATE or DELETE policy anywhere**, and no write privilege
is granted to `anon` or `authenticated` on any object. Both gates are shut: a
policy added later by mistake still cannot write without a GRANT. All six
internal helpers are `SECURITY DEFINER` with `SET search_path = ''` and fully
schema-qualified bodies; `EXECUTE` is revoked from `PUBLIC` first, because
Postgres grants it by default.

## Deviations from the brief (each deliberate, each visible here)

**D1 — migration 0003 is not literally empty.** The brief asks for "only a
comment". The file's explanation is a `--` comment block, but it also carries one
real statement: `COMMENT ON SCHEMA aigundem IS '…'`. Reason: an SQL script with
zero statements is rejected by some appliers, and a zero-statement migration is
indistinguishable from an accidentally truncated file. The statement creates no
object and changes no data. If the coordinator prefers a strictly empty file,
deleting that statement is safe.

**D2 — `aigundem.internal_*` wrappers were added (not in the brief).** PostgREST
is exposed on `'public, aigundem'` (addendum §B), so `private` is **not**
reachable through `supabase-js`: an Edge Function literally cannot call
`private.lease_due_sources(…)`. Each helper therefore has a one-line
`SECURITY DEFINER` wrapper in `aigundem`, granted to `service_role` alone. P3/P4
call `supabase.schema('aigundem').rpc('internal_lease_due_sources', { n: 5 })`
with the service-role key. `internal_lease_ai_jobs` spells its columns out
(`RETURNS TABLE (…)`) rather than returning `SETOF private.ai_jobs`, so PostgREST
never has to introspect a composite type in an unexposed schema. PostgREST will
*advertise* these names to `anon`; `EXECUTE` is revoked, so a call returns 42501.
Probes 19–21 in `rls-probes.sql` check exactly that.

**D3 — value sets are domains, not repeated inline CHECKs.** Migration 0001 is
"extensions and types", and `language`, `category`, `status`, `content_quality`,
`translation_state` are each used by more than one table. Each domain carries the
same constraint arch-001 specifies (e.g. `aigundem.category` allows exactly
`Modeller, Araştırma, Ürün, Açık Kaynak, Türkiye` and rejects `Tümü`). The
sql-lint suite asserts the literal value lists.

**D4 — `articles` and `article_summaries` policies are `USING (true)`.** That is
what addendum §A specifies ("articles, summaries" unqualified, only *sources* is
restricted to active and only *digests* to ready). The client's read path,
`feed_articles_v1`, additionally restricts to active sources, so an article whose
source was later paused disappears from the feed even though the base row stays
readable. Called out because it is a real, deliberate difference between the
table policy and the view.

**D5 — one cross-table invariant is a trigger, not a constraint.** arch-001 §2
says Turkish articles must have `translation_state = 'not_required'`. The
article's language lives on another table, so a CHECK cannot express it;
`private.enforce_summary_translation_state()` raises `23514` instead.

**D6 — `pg_trgm` is not used and not enabled.** The brief made it optional. Full
text search covers the search RPC; adding an uninstalled extension for nothing
would be a larger system.

## What is NOT verified

Everything that needs a live database. Specifically:

1. **That Postgres accepts any of this SQL.** No parser, no server, no dry run.
   First real syntax check happens when the coordinator calls `apply_migration`.
2. **That the RLS policies behave as described.** The lint proves the policies
   are *written*; only `rls-probes.sql` run remotely proves they *bite*.
3. **That PostgREST picks up `aigundem`.** `ALTER ROLE authenticator SET
   pgrst.db_schemas` is the documented mechanism, but on Supabase the durable
   home of that setting is the Dashboard "Exposed schemas" field — a later
   dashboard config write can overwrite the role setting. **Coordinator: verify
   with probe 1.7(f) and, if PostgREST 404s on `aigundem`, set it in the
   Dashboard instead of re-running the migration.**
4. **That `CREATE EXTENSION … WITH SCHEMA extensions` is a no-op here.**
   `pgcrypto` is already installed (facts file), so the `IF NOT EXISTS` guard
   should skip it entirely; it would only fail on a project with no `extensions`
   schema.
5. **Generated-column immutability, `FOR UPDATE SKIP LOCKED` inside the CTEs, the
   `security_invoker` view, and `RETURNS SETOF <table>` from the leasing
   functions** are all standard PG 15+/17 constructs but none was executed.
6. **Query plans.** No `EXPLAIN` was run; that the GIN index is actually chosen
   by `search_articles_v1`, and that the keyset indexes are used, is unmeasured.
7. **Concurrency.** The leasing functions are written for `SKIP LOCKED`
   disjointness; no concurrent run was performed.
8. **Seed data and cron.** Migrations 006 (six default sources) and 007 (cron)
   belong to P3/P5 and do not exist yet, so every table is empty and every
   `count(*)` probe will legitimately return 0 on first run.

## Open item the coordinator must route (lane risk for P3/P4)

`private.ai_jobs` and `private.ingestion_runs` are reachable only from inside
`private` — and `private` is not exposed to PostgREST. The three helpers this
brief specified cover *leasing* and *rate limiting*, but **nothing here lets an
Edge Function record a job outcome** (`ready`/`failed`, backoff `available_at`),
**enqueue a job**, or **write an `ingestion_runs` row**. Writes to
`aigundem.sources/articles/article_summaries/digests/digest_items` are fine —
`service_role` has direct table grants there.

P3/P4 therefore need either `aigundem.internal_*` wrappers of the same shape
(migration 006+, which this task is forbidden to write) or a different transport.
Flagging rather than pre-empting: the exact signatures are P3/P4's design.

## Rollback

Applied migrations are immutable; the correction is a forward compensating
migration. **Not run by this task, and destructive — it deletes every AI Gündem
row.** Sketch only:

```sql
-- 2026082100NN_rollback_aigundem.sql   (coordinator only, never automatic)
drop schema if exists aigundem cascade;
drop schema if exists private cascade;
alter role authenticator reset pgrst.db_schemas;
notify pgrst, 'reload config';
```

Two cautions. `ALTER ROLE authenticator RESET pgrst.db_schemas` returns the
project to whatever the Dashboard says — confirm that still lists `public`, or
the unrelated application on this project loses its API. And `drop schema
private cascade` removes the rate-limit history and every queued AI job; if the
intent is only to re-shape one table, drop that table, not the schema.
