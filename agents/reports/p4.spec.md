## Claude API rules (coordinator-verified against the Claude API reference)
- SDK: `npm:@anthropic-ai/sdk` (exact pin) in the Deno function; **no raw fetch**.
- Model: `Deno.env.get('ANTHROPIC_MODEL') ?? 'claude-opus-5'`.
- Request: `client.messages.create({ model, max_tokens: 4096, system: [{type:'text',
  text: SYSTEM_PROMPT, cache_control: {type:'ephemeral'}}], messages: [{role:'user',
  content: <delimited article block>}], output_config: { format: { type: 'json_schema',
  schema: <strict JSON schema: {summary:[string×3], translation:string|null}> } } })`.
  Adaptive thinking is the default — **never** send `budget_tokens`; do not set
  `temperature`. Parse with `JSON.parse` on the text block; validate shape again
  in code (3 bullets, each 1–500 chars; translation null ⇔ article language `tr`).
- Check `stop_reason`; treat `refusal`/`max_tokens` as non-retryable/retryable
  respectively; map SDK typed errors (`RateLimitError`, `APIConnectionError` →
  retryable with backoff+jitter; `AuthenticationError`, `BadRequestError` → not
  retryable). Prompt: stable system text first (cacheable), article text as
  untrusted data inside explicit delimiters with an instruction to ignore embedded
  instructions; cap article input to ~12k chars.
- **Key-optional path (addendum §E):** if `ANTHROPIC_API_KEY` is unset,
  `process-enrichments` returns `{skipped:'no_api_key', ready:0, retried:0,
  failed:0}` after one `console.warn`, touching no jobs; `request-enrichment`
  enqueues the job and answers `202 {status:'queued', poll_after_seconds: 300,
  reason:'no_api_key'}`. Live Claude is **not verified** in v1; all tests use a
  fake client behind an interface (`ClaudeClient { summarise(input): Promise<…> }`).

## Goal
- `supabase/functions/_shared/anthropic.ts` (portable: builds the request object
  and parses/validates the response; SDK instantiation isolated in a tiny

  schema + runtime validator), `_shared/enrichment.ts` (pure orchestration over an
  injected db + client: cache lookup by `(article_id, content_hash,
  prompt_version, model)`, job lifecycle, retry/backoff, error mapping).
- `supabase/functions/request-enrichment/index.ts`: `verify_jwt` true (anon JWT);
  `X-Device-Id` uuid required → `private.bump_rate_limit` (120 cached checks/h,
  30 new misses/24h); body `{article_id, client_request_id}`; if a fresh summary
  exists → `200 {status:'ready', summary}`; else upsert the job (unique cache key)
  → `202 {status:'queued', poll_after_seconds}` (+ `reason:'no_api_key'` when
  applicable). Error envelope per arch-001 §3.
- `supabase/functions/process-enrichments/index.ts`: internal-secret auth
  (`X-Internal-Secret` vs `AUTOMATIONS_SECRET`, constant-time); `{max_jobs?:1..3}`;
  lease via `private.lease_ai_jobs`, call Claude, write `article_summaries`
  (respecting the Turkish trigger: `translation_state='not_required'`,
  `translation_tr=null` for `tr`), mark job `ready`/requeue with backoff/`failed`
  at `max_attempts`; a global daily cap (`AI_DAILY_CAP`, default 200) checked via
  `private.rate_limit_buckets` subject `global`.
- Jest tests (Node, in the existing `sql`/functions project): schema validation
  (3 bullets, Turkish null rule), prompt builder (delimiters, cap, no raw
  instructions leak), cache hit/miss, idempotent job upsert, lease→ready,
  lease→retry with backoff, lease→failed at max attempts, rate-limit math,
  no-key path for both functions, error mapping table, concurrency (two workers,
  same job → one write). Fake client and fake db only.
