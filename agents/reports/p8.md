## 3. What was wired

- **`ThemeProvider`** owns preference (`dark|light|system`) and resolves it to a
  scheme. Only `system` consults `useColorScheme()`, and it re-resolves on OS change
  because the hook re-renders the tree.
- **Persistence** through `src/storage/kv.ts`: `expo-sqlite/kv-store` on native
  (lazily `require`d so the web bundle never resolves the native module),
  `localStorage` on web, in-memory as the last resort with a one-time warning.
  `KV_KEYS` names the one key; P6/P9 add theirs there.
- **Before the first painted frame:** `app/_layout.tsx` holds a blank dark canvas
  through the font gate *and* through `isReady`, so the app never paints one theme
  and swaps in front of the user. `StatusBar` style follows the resolved scheme.
- **Settings** is a real three-state radio group (`accessibilityRole="radiogroup"` /
  `"radio"`, `accessibilityState.selected`). `TOASTS.theme` and its `themeTap` are
  gone.
- **Shared components** (`Toast`, `Toggle`, `ArticleCard`, `EmptyState`,
  `DigestTimeSheet`) build their styles from the palette via `useThemedStyles`,
  which memoises a `StyleSheet.create` per palette rather than scattering inline
  colour objects.
- **`app.json`**: `userInterfaceStyle` is now `"automatic"`; splash and background
  stay `#0B1220` as the brief requires.

## 5. Decisions

1. **`tokens.ts` became a 15-line shim re-exporting the dark palette**, exactly as
   the brief permits. Nine unmigrated files keep compiling and keep their current
   appearance; P7 deletes the shim when the last one moves. Its header says "do not
   add anything here" so it does not quietly become a second source of truth.
2. **`useThemedStyles(factory)`** memoises `StyleSheet.create(factory(palette))` per
   palette. The alternative — inline colour objects at every call site — re-allocates
   on each render and scatters the palette through JSX.
3. **The Settings segment has no icons.** The board draws a small sun glyph on the
   active light pill; I kept the prototype's three plain pills so the diff stays
   bounded to behaviour. Cheap to add later.
4. **`system` with no OS answer resolves to dark**, not light: dark is the product's
   primary theme (AGENTS.md), and flashing light on a null `useColorScheme` would be
   the more visible wrong.
5. **Invalid stored/selected preferences warn and fall back** rather than blanking
   the palette — a `undefined` palette slot renders as a transparent surface, which
   is far harder to diagnose than a log line.
6. **`react-test-renderer` has no type declarations**, and adding
   `@types/react-test-renderer` is outside the brief's dependency allowance
   (`expo-sqlite` only). I declared the exact surface the test uses in
   `src/theme/__tests__/react-test-renderer.d.ts` instead — inside an allowed path,
   deletable the moment a typed renderer is adopted.
7. **`expo-sqlite` is `require`d lazily inside `kv.ts`.** A top-level import would
   put the native module in the web graph and put `expo export --platform web`
   (A3) at risk.
