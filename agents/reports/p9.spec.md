## Goal
- **Onboarding** `app/onboarding.tsx` (+ root guard in `app/_layout.tsx`): shown
  until `onboardingCompletedAt` is set; lists the default sources from
  `useSources()` with toggles (all on by default), requires ≥ 1 selected, a
  short explanation of the morning digest with a time picker (the 5 slots) and
  an optional "Bildirimlere izin ver" step; "Başla" persists sources + digest
  time + completion atomically in user-state and enters tabs; Back/restart
  cannot bypass it. Works in mock mode too.
- **NotificationService** `src/notifications/*` on `expo-notifications`:
  Android channel created before the permission request; permission requested
  only after the explanatory UI; iOS `authorized/provisional/denied` handled;
  one repeating daily calendar trigger at the chosen local time; schedule-new →
  persist id → cancel-old; reconcile to exactly one owned schedule on launch,
  foreground and timezone change; denial keeps the time but `digestEnabled=false`
  with OS-settings guidance. Tap on the notification deep-links to the Digest
  tab (`expo-router` URL). No push token, no background fetch.
- **Settings integration**: the digest-time sheet and the "Digest bildirimi"
  switch (decorative until now) become real and drive the service; "Hazır ·
  {time}" badge reads the same state.
- **Config**: `app.json` plugin entry for `expo-notifications` (icon/colour from
  the dark palette), Android `SCHEDULE_EXACT_ALARM` only if you use exact
  triggers — prefer inexact daily triggers and say so.
