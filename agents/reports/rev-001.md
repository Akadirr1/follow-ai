## Blocking defects

### B1 — Turkish locale folding makes lowercase `ai` / `openai` fail to match `OpenAI Blog`

**Measured · blocking · high.** `src/store/selectors.ts:27-32` applies
`toLocaleLowerCase('tr')` to the query and corpus. In Turkish casing, ASCII `I`
lowercases to dotless `ı`, so the source becomes `openaı blog`, while the common
lowercase query `ai` remains `ai`. The prototype uses plain `toLowerCase()` at
`design/AI Gündem - Prototip.dc.html:362-364`, and the brief requires live,
case-insensitive matching over source names.

Independent reproduction:

```text
hay: "openaı blog"
query: "ai"
turkishLocaleIncludes: false
prototypeIncludes: true
```

Impact: a user searching `ai` or `openai` cannot find the OpenAI article by its
source, even though the prototype does. The existing search tests at
`src/store/__tests__/store.test.ts:132-157` cover `ALPHAFOLD`, `hugging face`, and
`türkiye`, none of which exercises ASCII capital `I`.

Smallest safe correction: restore the prototype's `toLowerCase()` on both sides
and add a selector test asserting that `ai` or `openai` returns article `oa`. If a
broader multilingual case-folding policy is desired later, specify it separately
and test Turkish `I/İ/ı/i` plus English acronyms.

### B2 — stale toast dismissal is silently swallowed despite the brief's warning rule

**Measured · blocking by explicit constraint · medium.** The stale-sequence guard
at `src/store/reducer.ts:128-131` returns the current state without a
`console.warn`. The implementation brief says every guard or early return that
swallows a state must warn (`agents/reports/impl-001.spec.md:81-82`), and the
review brief specifically asks to confirm that every swallowed state warns. The
other invalid/ignored reducer transitions warn at `src/store/reducer.ts:35-37`,
`:43-45`, `:54-56`, `:67-69`, `:81-83`, and `:110-113`; this one does not.

Impact: an out-of-date `clearToast` action is deliberately ignored, but that
transition is invisible in diagnostics. The test at
`src/store/__tests__/store.test.ts:210-215` confirms state preservation but does
not assert a warning.

Smallest safe correction: warn with the stale and current sequence numbers before
returning, and assert that warning in the stale-sequence test. If stale dismissal
is to be treated as routine rather than observable, the brief must be changed;
the current implementation does not meet the written constraint.

## Non-blocking findings / debt

### N1 — rapid repeated article presses may enqueue duplicate detail routes

**Needs measurement · non-blocking · medium risk.** Feed, saved, and search each
dispatch and then call `router.push` without an in-flight guard at
`app/(tabs)/index.tsx:21-24`, `app/(tabs)/saved.tsx:23-29`, and
`app/search.tsx:22-26`. Reducer repetition is harmless, but two accepted presses
could add the same detail route twice, unlike the prototype's single `view =
'detail'` state transition. No component or navigation test exercises this.

Observation that settles it: double-tap a feed/search/saved card before the first
transition finishes on web and on one native target, then inspect navigation
history and verify that one Back action returns to the originating screen. If a
duplicate is observed, use a transition guard or navigation operation with
verified de-duplication semantics.

### N2 — store effects, hooks, screens, routing, modal, and toast timing have no executable tests

**Measured coverage gap · non-blocking.** `jest.config.js:1-4` restricts tests to
the store test file, which directly imports only reducer/selectors/data. The pack's
structural neighborhood and the test imports confirm that `StoreProvider`, all
screens, `Toast`, `DigestTimeSheet`, router behavior, and render paths are not
executed. The pure store coverage is useful, but it cannot establish that
`StoreProvider` restarts and cancels timers (`src/store/StoreProvider.tsx:31-36`),
that the modal maps backdrop/Back/Vazgeç/Kaydet correctly
(`src/components/DigestTimeSheet.tsx:17-87`), or that provider consumers render.

Observation that settles it: add a renderer/integration layer with fake timers
for toast replacement, modal cancel/save tests, and route interaction tests; then
run at least one native smoke test. This is not a claimed runtime defect.
